# Solity Doorlock (Cloud) — Hubitat 드라이버

스마트솔리티(SOLITY) 도어락을 **SmartThings 없이** 솔리티 클라우드 API로 직접 제어하는 Hubitat Elevation 커스텀 드라이버입니다.

- 원격 열기 / 잠그기
- **실제 데드볼트 기준 잠김 상태** — 열림 후 상태를 다시 읽어, 빗장이 실제로 나온 시점에 `locked`
- **문 열림/닫힘 센서** (`ContactSensor`) — 도어락의 문 감지 래치 값
- 열림 감지 (기본 10초 주기, 도어락 배터리 소모 없음)
- **누가, 어떤 방식으로 열었는지** 표시 (지문 / 카드 / 비밀번호 / 원격 / 스마트오픈 / 실내)
- 대시보드용 최근 출입 내역 표
- 도어락이 응답하지 않으면 1분 → 2분 → 5분 간격으로 다시 조회
- 토큰 자동 갱신

> 비공식 프로젝트입니다. 솔리티/제조사와 무관하며 앱 API가 바뀌면 동작하지 않을 수 있습니다. 본인 계정의 본인 도어락에만 사용하세요.

## 요구 사항

- Hubitat Elevation 허브 (인터넷 연결 필요 — 클라우드 경유 방식이며 로컬 제어가 아닙니다)
- 스마트솔리티 앱 계정(이메일 + 비밀번호)과 앱에 **WiFi로 등록된** 도어락
  - 블루투스 전용 모델(WiFi 모듈 없음)은 클라우드에 연결되지 않아 쓸 수 없습니다.
  - 문 센서는 푸시풀 모티스의 문 감지 래치(`subLatch`)를 씁니다. 구조가 다른 도어락은 값이 없거나 뜻이 다를 수 있습니다.

## 설치

1. Hubitat 웹 UI → **Drivers Code** → **New Driver**
2. [`drivers/solity-doorlock-cloud.groovy`](drivers/solity-doorlock-cloud.groovy) 내용을 붙여넣고 **Save**
   (또는 **Import** 버튼에 이 저장소의 raw 파일 URL 입력)
3. **Devices** → **Add Device** → **Virtual** → Type에서 `Solity Doorlock (Cloud)` 선택 후 생성
4. 기기 페이지 **Preferences**에 이메일과 비밀번호를 입력하고 **Save Preferences**

저장하면 자동으로 로그인하고, 계정의 첫 번째 도어락을 찾아 폴링을 시작합니다. 첫 로그 조회에서는 이벤트를 내지 않고 기준점만 잡은 뒤 최근 출입 내역을 채웁니다.

**v1.1에서 업데이트**: 드라이버 코드를 교체한 뒤 기기 페이지에서 **Save Preferences**를 한 번 눌러 주세요. 없어진 "열림 후 자동 잠김 복귀" 설정과 예전 상태값이 정리됩니다.

### 같은 계정을 폰 앱과 같이 쓸 때

솔리티 서버는 **계정당 한 곳에서만 로그인**을 유지합니다. 폰 앱과 허브가 같은 계정을 쓰면 서로 로그아웃시킵니다.

드라이버는 이를 줄이기 위해, 허브 토큰이 만료 전에 끊기면 "앱에서 로그인했다"로 보고 **바로 다시 로그인하지 않습니다.**

- `apiStatus`가 `session_taken`이 되고, 설정한 시간(기본 30분)이 지나면 다시 로그인합니다. 재개 시각은 `sessionResumeAt`에 표시됩니다.
- 그동안은 열림 감지와 상태 조회가 멈춥니다. 다시 로그인한 뒤 밀린 열림 기록은 **알림 없이** 출입 내역에만 반영합니다.
- Hubitat에서 `lock` / `unlock`을 보내거나 `login` 명령을 누르면 바로 다시 로그인합니다.
- 허브가 다시 로그인하는 순간 앱은 로그아웃됩니다. 앱을 자주 쓰면 대기 시간을 늘리거나 "수동"으로 두세요.

완전히 피하려면 계정을 나누는 수밖에 없습니다.

1. 다른 이메일로 스마트솔리티 계정을 하나 더 만듭니다.
2. 소유자 계정의 앱에서 그 계정을 **구성원으로 초대**해 도어락을 공유합니다.
3. 구성원 계정으로 앱에 로그인해 원격 조작과 출입 기록이 보이는지 먼저 확인한 뒤, 허브에 그 계정을 넣습니다.

| 상태/배터리 폴링 주기 | 30분 | **도어락을 깨웁니다.** 짧게 잡으면 배터리가 빨리 닳습니다 (10분~12시간) |

| 디버그 로그 | 켬 | 30분 뒤 자동으로 꺼집니다 |

## 명령

| 명령 | 설명 |
|---|---|
| `lock` / `unlock` | 원격 잠금 / 열기. 잠금은 데드볼트가 나온 것을 읽은 뒤 `locked`가 됩니다 |
| `refresh` | 상태와 출입 로그를 즉시 조회 (도어락을 깨움) |
| `login` | 강제 재로그인 |
| `diagnose` | 연결 상태, 잠김 확인 상태, 기기 목록, 최근 출입 로그 5건의 원본을 로그에 출력 |

## 속성

### 잠김 / 문

| 속성 | 값 | 설명 |
|---|---|---|
| `lock` | `locked` / `unlocked` | **실제 데드볼트** 값. 열림 감지 즉시 `unlocked`, 잠김을 읽으면 `locked` |
| `contact` | `open` / `closed` | 문 열림/닫힘 (`ContactSensor`) |
| `door` | `open` / `closed` / `unknown` | `contact`와 같되, 모르는 상태를 `unknown`으로 표시 |
| `confirmed` | `true` / `false` | 지금 값을 도어락에서 다시 읽었는지. 열림 직후·조회 실패 시 `false` |
| `verifying` | `true` / `false` | 열림 후 잠김을 확인하는 중 |
| `notAnswering` | `true` / `false` | 도어락이 응답하지 않아 느린 간격으로 다시 조회하는 중 |
| `lastVerifyResult` | `locked` / `still_unlocked` / `no_answer` | 마지막 잠김 확인 결과 |
| `lastVerifySeconds` | `9.5` | 열림 감지부터 확인이 끝날 때까지 걸린 초 |
| `lastVerifyTrace` | `1.0s 문열림 → 7.0s 닫힘·안잠김 → 9.5s 잠김` | 확인 과정 |

### 누가 / 어떻게

| 속성 | 예시 | 설명 |
|---|---|---|
| `lastAccess` | `열림 · 홍길동 · 지문` | 마지막 출입 요약 |
| `lastAccessUser` | `홍길동` | 사용자 (없으면 `-`) |
| `lastAccessMethod` | `지문` | 방식 |
| `lastAccessType` | `open` | `open` / `close` / `other` |
| `lastAccessTime` | `2026-10-14 08:20:28` | 기록 시각 |
| `lastAccessMessage` | `홍길동 지문으로 도어락을 열었습니다.` | 솔리티 서버 메시지 원문 |
| `lastUnlockedBy` / `lastUnlockMethod` / `lastUnlockTime` | | 마지막으로 **연** 사람·방식·시각 |
| `lastLockedBy` / `lastLockMethod` / `lastLockTime` | `-` / `도어락` | 마지막 잠김. Hubitat에서 잠그면 `Hubitat` |
| `lastCodeName` | `홍길동` | `lastUnlockedBy`와 동일 (Lock 관련 앱 호환용) |
| `accessHistory` | HTML 표 | 최근 출입 내역 (대시보드 Attribute 타일용) |

열림 방식은 서버의 `mediaType` 코드로 판정합니다.

| 코드 | 방식 |
|---|---|
| 1 | 비밀번호 |
| 5 | 카드 |
| 7 | 원격(앱) — 앱이나 Hubitat에서 연 경우 |
| 8 | 지문 |
| 11 | 스마트오픈 |
| 32 | 실내 |

목록에 없는 코드는 메시지 문구로 추정하고, 그래도 모르면 `코드 N`으로 표시합니다.

### 상태 원본

| 속성 | 설명 |
|---|---|
| `battery` | 배터리 % |
| `cardCount` / `fingerprintCount` / `passwordCount` | 등록된 인증 수단 개수 |
| `subLatch` / `systemMode` | 도어락이 보고하는 원본 값 |
| `apiStatus` | `ok` / `auth_failed` / `error` / `session_taken` |
| `sessionResumeAt` | 앱에 세션을 양보한 뒤 다시 로그인할 시각 |

## 자동화에서 쓰기

`lock` 이벤트의 설명(descriptionText)에 사용자와 방식이 들어갑니다. 열림 이벤트는 이미 `unlocked`인 상태에서 또 열려도 매번 발생합니다.

```
솔리티 열림 · 홍길동 · 지문
솔리티 잠김 · 도어락
```

**Rule Machine 알림 예시**

- Trigger: `솔리티` lock *unlocked*
- Action: Notify — `현관 %text%`

**문을 열어 둔 채 방치 알림**

- Trigger: `솔리티` contact *open* and stays that way for 5 minutes
- Action: Notify — `현관문이 5분째 열려 있습니다`

특정 사람만 걸러내려면 조건에 Custom Attribute `lastUnlockedBy`를 쓰면 됩니다. 속성은 `lock` 이벤트보다 먼저 갱신되므로 룰이 실행될 때 이미 새 값입니다.

이벤트 `data`에도 `user`, `method`, `time`, `message`, `mediaType`, `codeName`이 들어 있어 커스텀 앱에서 읽을 수 있습니다. 이벤트 `type`은 원격(앱·Hubitat)이면 `digital`, 그 외는 `physical`입니다.

**대시보드**: Attribute 타일을 추가하고 `accessHistory`를 선택하면 최근 출입 내역이 표로 나옵니다.

## 동작 원리

### 폴링 두 가지

| 종류 | 호출 | 도어락 깨움 | 기본 주기 |
|---|---|---|---|
| 열림 로그 | `GET /api_v2/retrieveLog/page/{id}` | 안 함 | 10초 |
| 상태/배터리 | `PUT /api_v2/controlDevice/{id}` (`get_status`) | 깨움 | 30분 |

열림 로그는 클라우드에 저장된 기록만 읽기 때문에 자주 돌려도 배터리에 영향이 없습니다. 폴링 사이에 여러 건이 쌓이면 오래된 것부터 순서대로 모두 처리합니다. 상태 조회는 비동기로 보내 허브 스레드를 붙잡지 않습니다.

`get_status`에는 두 값이 들어 있습니다.

| 값 | 의미 |
|---|---|
| `deadBolt` | 데드볼트(모터로 나오는 잠금 빗장). 1 = 잠김, 0 = 열림 |
| `subLatch` | 문 감지 래치. 문이 닫히면 문틀에 눌려 1, 열리면 0. 자동잠김은 이 래치가 눌리는 것을 신호로 걸립니다 |

### 열림 후 잠김 확인

솔리티 도어락은 **열림만 기록하고 잠김 기록은 없습니다.** 그래서 열림을 감지하면 상태를 다시 읽어 실제로 잠긴 시점을 찾습니다.

1. 로그에서 열림 감지 → `lock`을 바로 `unlocked`로, 문은 바로 `open`으로 표시합니다.
   - **원격 열기(코드 7)** 는 문을 안 열 수도 있어서 문을 `unknown`으로 두고 실제 값을 읽어 옵니다.
2. 바로 상태를 조회하고, 결과에 따라 다음 조회 시점을 정합니다.

| 조회 결과 | 판단 | 다음 조회 |
|---|---|---|
| 데드볼트 나옴 | 잠김 | **끝** (`locked`) |
| 빗장 들어감 + 문 닫힘 | 곧 자동잠김이 걸림 | 1.5초 후 (3번까지. 그래도 안 잠기면 수동잠금 모드로 보고 간격을 늘림) |
| 빗장 들어감 + 문 열림 | 아직 드나드는 중 | 5초 → 10초 → 20초 … 최대 2분 간격 |

3. 15분이 지나도 안 잠기면 평소 상태 조회 주기로 돌아갑니다. 그동안 `lock`은 `unlocked`로 유지됩니다(타이머로 잠김 처리하지 않음).

- 열림 직후 첫 조회는 응답 없이 멈추는 경우가 많아, 확인용 조회는 **3초 안에 응답이 없으면 끊고 바로 다시** 보냅니다(최대 3번).
- 그래도 응답이 없으면 추정한 문 "열림"을 `unknown`으로 돌려, 잘못된 값이 오래 남지 않게 합니다.

**Hubitat에서 연 경우**는 조금 다르게 확인합니다(원본 HA 통합 v1.7.4~1.7.5).

- 열기 명령 직후에는 도어락 WiFi+ 모듈이 명령 전달과 기록 업로드로 바빠, 조회를 몰아 보내면 모듈이 멈출 수 있습니다. 그래서 **첫 확인은 5초 뒤**에 하고, 응답이 없으면 **3초 뒤 한 번만** 다시 보냅니다.
- 명령 뒤 5초 안에 읽은 "잠김"은 명령이 닿기 전 값으로 보고 무시한 뒤 곧 다시 읽습니다(`lastVerifyTrace`에 `잠김(이전값)`).
- 열기·잠그기 명령을 보내는 동안에는 상태 조회를 잠시 미룹니다.
- 데드볼트 값이 없는 응답(빈 응답 등)은 실패로 보고 직전 값을 유지합니다.

### 도어락이 응답하지 않을 때

도어락 WiFi 모듈이 멈추면 로그 조회는 되는데 상태 조회와 열기·잠그기만 타임아웃이 납니다(앱 원격 조작도 안 됨).

- 상태 조회가 실패하면 `notAnswering: true`가 되고, **1분 → 2분 → 5분 간격(이후 5분마다)** 으로 다시 조회해 살아나는 즉시 반영합니다.
- 그동안 직전 값은 유지하고 `confirmed: false`로 표시합니다.
- 오래 가면 **도어락 배터리를 뺐다가 다시 끼워** 재부팅하세요.

### API

- 로그인: `POST /api_v2/login` → `token` + `tokenPwd` (헤더 `Authorization`, `AuthorizationPwd`). 401/403이면 한 번 재로그인 후 재시도합니다.
- 원격 개폐: `PUT /api_v2/controlDevice/{id}`, body `{"controlType":"open|close","optionValue":"1"}`
- `lang`은 반드시 숫자 `"0"` (문자 `"ko"`는 반쪽 토큰 발급됨)

## 알아둘 점

- **누가 잠갔는지는 알 수 없습니다.** 도어락이 잠김을 기록하지 않아, Hubitat에서 잠근 경우 외에는 방식이 `도어락`(자동잠김 또는 실내 수동)으로 표시됩니다.
- **실내에서 연 경우 사용자가 없습니다.** 도어락이 사용자를 기록하지 않아 `-`로 표시됩니다.
- **문 센서는 상태를 조회할 때만 갱신됩니다.** 열림 직후 확인하는 동안에는 자주 갱신되지만, 그 밖에는 상태 폴링 주기(기본 30분)마다입니다. 실시간 문 센서가 필요하면 별도 Zigbee 문 센서를 쓰세요.
- **도어락이 기록을 올리지 못하면 감지할 수 없습니다.** 열림 감지는 솔리티 클라우드의 출입 기록을 읽는 방식이라, 도어락 WiFi 모듈이 기록을 올리지 못하면 앱에도 허브에도 나타나지 않습니다. 자주 반복되면 도어락 배터리를 뺐다 끼워 재부팅하세요.
- **감지 지연**: 도어락이 클라우드에 보고하는 시간 + 폴링 주기만큼 늦습니다.
- 비밀번호는 Hubitat 기기 설정에 저장됩니다(Hubitat의 password 입력 방식). 허브 접근 권한 관리에 유의하세요.

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| `apiStatus`가 `auth_failed` | 이메일/비밀번호 확인 후 Save Preferences |
| 폰 앱이 자꾸 로그아웃됨 | 허브와 앱이 같은 계정을 쓰는 중 — [같은 계정을 폰 앱과 같이 쓸 때](#같은-계정을-폰-앱과-같이-쓸-때) |
| `notAnswering`이 계속 `true` | 도어락 WiFi 모듈 멈춤 — 배터리를 뺐다 끼워 재부팅 |
| `lock`이 계속 `unlocked` | 문이 열려 있거나 수동잠금 모드 — `lastVerifyTrace` 확인 |
| 출입 내역이 비어 있음 | `diagnose` 실행 → 로그에 `로그:` 줄이 나오는지 확인 |
| 다른 도어락이 잡힘 | `diagnose`의 `기기:` 줄에서 ID 확인 → `myDeviceId`에 입력 |
| 열림이 늦게 뜸 | 열림 감지 주기를 5초로 |
| 배터리가 빨리 닳음 | 상태/배터리 폴링 주기를 늘리기 |
